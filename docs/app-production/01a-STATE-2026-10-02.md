## 2. The delivery pipeline — replaces §9's posture

Section 9 said the gate proved almost nothing. Between 2026-10-01 and 2026-10-02 (PRs #197–#203)
that stopped being true:

- `ci.yml` now runs the secret scan **plus** a web job (migrations applied, typecheck without
  incremental cache, tests, build) and a contracts job (Move tests), on push and on schedule.
- `deploy.yml` deploys to production automatically behind that CI gate, via `workflow_run` with
  `production` environment approval; `workflow_dispatch` remains for a manual ship.
- `vercel.json` sets `git.deploymentEnabled.main: false` — Vercel's push-to-main auto-deploy is
  off; production ships only through the gated pipeline.
- `drift-alarm.yml` diffs main against the newest production deployment record nightly and files
  an issue on a parting. Its first fix landed the morning of this measurement (`996bb6f`):
  production resolves as the newest **successful** record, not the newest record.
- Next bumped 16.3.5 → 16.3.6 for GHSA-vcvr-r3jv-pc5j (critical RCE in `next/og` ImageResponse).

Deployment is no longer gated on a CI run that contains no suites. The doc's mechanical
explanation for "another beta" is half-retired: the gate now runs the suites, while the
visual-regression, accessibility and performance-budget gaps remain open.
